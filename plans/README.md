## Findings considered and rejected

So nobody re-audits these:

- **Constant `session_id: factory-droid` sent upstream** (`proxy.go:121-124`,
  `536-548`): `requestID()` falls back to the body's `prompt_cache_key`, which
  by then is the injected default, so every keyless request sends
  `session_id`/`x-client-request-id` = `factory-droid` upstream. **Not planned**
  — needs a Codex-backend behavior check to know whether conflating sessions
  hurts; may be intentional. Investigate before fixing.
- **`OPENAI_API_KEY` silently becomes the client auth key** (`main.go:175`):
  surprising but *fails closed* (enables auth, never disables it) and is a
  one-line documentation fix at most. **Not planned** — low impact; fold into a
  docs pass if one happens.
- **Per-request `flock` + no in-memory token cache** (`auth.go:61`): every
  request takes an exclusive auth-file lock, re-reads and re-parses `auth.json`,
  and re-decodes the JWT. Real architectural smell, but negligible at
  personal-tool concurrency, and an in-memory cache adds invalidation +
  concurrency risk. **Rejected** — not worth the risk now.
- **1,013-line `dashboard.go` HTML/CSS/JS blob**: by design — `AGENTS.md`
  explicitly chooses a dependency-free, single-binary dashboard. **Rejected** —
  documented decision, not debt.
- **JWT signature not verified** (`auth.go:266-280`): by design — the broker
  reads claims from its own trusted, locally-stored token to decide refresh
  timing; the Codex backend verifies the token. **Rejected** — not a finding.
- **prompt_cache_key behavior** (`proxy.go:251-269`): settled by the recent
  rework (commits `0a50ba9`, `937ea70`); shared `factory-droid` key is the
  intended cache-affinity strategy. **Not a finding.**
